## 3. Recurly capabilities relevant to a vault / orchestration conversation (Recurly docs, quoted)

### 3.1 Recurly stores card data (own vault), with exceptions

- "Because Recurly stores customer credit card data, you can switch payment gateways at any time." and "Note that not all payment data migrates easily, especially tokenized payment instruments." [PRIMARY] https://docs.recurly.com/docs/payment-gateways
- Storage matrix (page updated 15 Jul 2026) [PRIMARY] https://docs.recurly.com/recurly-subscriptions/docs/gateway-token-support :
  - Cards via Recurly.js or API on "Any except Stripe and Braintree" gateways: stored in "Recurly".
  - Stripe: "Stripe retains the raw card data and Recurly does not have access to the primary account number (PAN)."
  - Stripe or Braintree cards: stored in "Recurly and Stripe or Braintree".
  - Adyen Web Components, Stripe Payment Elements, PayPal: instruments stored with the provider; PayPal: "Payment instruments are stored with PayPal and are not accessible to Recurly."
  - Network tokens for cards on "Any" gateway: stored in "Recurly and Visa".
- Security page [PRIMARY] https://recurly.com/security/ : "Recurly is PCI-DSS Level 1 compliant, and recognized on the Visa Global Registry of Service Providers." ; "Cardholder data is sent directly to Recurly to minimize risk to your business." ; "Sensitive information is stored using several layers of encryption in a segmented network with no public internet access."

### 3.2 Recurly.js hosted fields

[PRIMARY] https://docs.recurly.com/v1.2/docs/overview-recurlyjs/ : Elements "inject transparent iframes" into the checkout form; on submit Recurly.js "immediately encrypts and securely stores" payment details on Recurly's servers and returns a token ("an authorization key"); Elements help meet "the latest PCI DSS SAQ A compliance requirements" and "your PCI compliance scope is significantly reduced."

### 3.3 Gateway tokens, network tokens, portability (same token-support page, updated 15 Jul 2026)

- Gateway token: "A value referencing a payment instrument stored with a specific gateway partner." Gateway tokens "are not transferable between gateways."
- Import support: Stripe (cus_, pm_), Adyen (ShopperReference IDs and Recurring Detail References), Braintree (legacy tokens), Commerce Hub/Fiserv ("Only TransArmor tokens are supported."), FreedomPay ("Only certain FreedomPay token types are supported."), Amazon Pay V1/V2. "Stripe, Adyen, Braintree -- speak to Support about enabling our Token Backfill behavior."
- "Generic and imported tokens may not support some behaviours available to standard payment methods."
- "If only a gateway token is present, gateway failover to other providers is not possible."
- "If only a gateway token is present for cards (common with imports), Recurly Account Updater cannot be used."
- "Portability is limited, and some Recurly features requiring full instrument details may be unavailable."
- Network token: "A card token issued by a card network (e.g., Visa) that can be used across multiple gateways." Benefits listed: "Enable failover across gateways when using multiple providers." and "Support migrating existing subscriptions to a different gateway that supports network tokens."
- Which gateways support network tokens inside Recurly: not listed on the page. UNVERIFIED. Changelog 14 May 2025 (Adyen): "Network Token usage on a per transaction basis will be reported in UIs and gateway params" [PRIMARY] https://docs.recurly.com/recurly-subscriptions/changelog/2025 . A search snippet says Adyen network tokens require Adyen Web Components third-party checkout [SNIPPET].

### 3.4 Bringing external tokens via API

[PRIMARY] https://docs.recurly.com/recurly-subscriptions/v2.29/docs/using-gateway-tokens-and-external-ntids-with-recurly-apis :
- Tokens go in `billing_info.payment_gateway_references.token`; "Since `gateway_code` may be deprecated in the future, using `payment_gateway_references.token` is preferred."
- "this only functions in our V3 API with a special feature flag." Flag name "Allow NTIDs in APIs"; "Reach out to support to enable this feature flag."
- "Currently we only support this in the `/subscriptions` and `/purchases` endpoint when adding future-dated subscriptions."

- `network_transaction_id` "Must be passed in when using a gateway that does not handle NTIDs on their own when using a gateway token."
- Token migration between gateways: Recurly "offers a secure token migration process for supported gateways (e.g., Stripe → Adyen, Braintree → Recurly). Contact Recurly Support to initiate a token migration request." [SNIPPET from docs.recurly.com, exact page not fetched]
